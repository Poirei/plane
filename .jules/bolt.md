## 2024-10-27 - [Aggregate count queries in WorkspaceUserProfileStatsEndpoint]
**Learning:** In the `WorkspaceUserProfileStatsEndpoint`, calculating multiple distinct counts (`created_issues`, `assigned_issues`, `pending_issues`, `completed_issues`) independently using `.count()` triggers an N+1 queries-like problem, generating multiple sequential database queries. This is a common codebase-specific pattern where performance regressions occur due to individual queryset counts.
**Action:** Instead of calling `.count()` individually, combine them into a single query using Django's `.aggregate()` with conditional `Count('id', filter=Q(...), distinct=True)`. Crucially, you must explicitly construct a base `.filter()` that combines all necessary conditions with an OR (`|`) to ensure the initial scope isn't unintentionally widened over the entire table before aggregation.
